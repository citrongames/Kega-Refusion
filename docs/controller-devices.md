# Контроллеры и J-Cart — 0.19.1

## Подключение

| Система | Устройство | Допустимое подключение |
| --- | --- | --- |
| Mega Drive / Sega CD | Геймпад с 3 или 6 кнопками | Порт 1, порт 2, порты адаптеров и J-Cart |
| Mega Drive / Sega CD | Mega Drive Mouse | Обычный порт 1 или 2; две независимые мыши поддерживаются |
| Mega Drive / Sega CD | Menacer | Порт 2 |
| Mega Drive / Sega CD | Justifier | Порт 2; второй пистолет в цепочке первого |
| Master System / Mark III / PBC | Геймпад | Порт 1, порт 2, Master Tap |
| Master System / Mark III / PBC | Light Phaser, Paddle | Обычный порт 1 или 2 |
| Game Gear / SG-1000 | Штатное управление | Без перечисленных дополнительных устройств |

В этой версии при использовании многопортового адаптера интерфейс предлагает только геймпады для всей выбранной схемы. Это ограничение реализации смешанных схем, а не утверждение, что любая такая комбинация невозможна на оригинальном оборудовании.

J-Cart включается автоматически по распознанному картриджу. Его два геймпада идут после внешних портов: P3–P4 без адаптера; P6–P7 с одним Team Player; P5–P6 с 4 Way Play. При паре Justifier без адаптера J-Cart занимает P4–P5. Два Team Player вместе с J-Cart требуют 10 устройств, превышая предел ядра в 8: такая комбинация недоступна; сохранённое предпочтение адаптера вернётся при следующей обычной игре. Порты J-Cart не предлагаются как универсальные разъёмы для мышей или пистолетов.

## Управление

Для мыши доступны движение указателя по области игры либо левый аналоговый стик. Скорость управления стиком регулируется от 25% до 400%. Движение указателя переводится в относительные координаты игры. Общая настройка «Захватывать мышь» включена по умолчанию: клик по изображению захватывает мышь и скрывает системную стрелку; первый клик не передаётся игре. Esc, потеря фокуса, открытие настроек или смена устройства освобождают мышь. В полноэкранном режиме следующий Esc открывает меню. При выключенной галочке сохраняется свободный режим указателя. По умолчанию левая, правая и средняя кнопки мыши соответствуют A, B и C; Start назначается отдельно.

Для Paddle положение стика либо свободного указателя по горизонтали задаёт угол ручки от 0 до 255. В режиме захвата относительное движение мыши изменяет виртуальное положение ручки и останавливается на её крайних положениях. Пистолеты используют такой же захват с виртуальным прицелом; небольшой запас за краем сохраняет возможность выстрела вне экрана для перезарядки. Две физические кнопки Paddle соединены параллельно и имеют одно назначение. По умолчанию используется левая кнопка мыши. Одна физическая мышь управляет одним выбранным устройством; второе можно назначить на стик, в сети у каждого участника своя мышь.

## Сеть, запись и перемотка

Хост задаёт аппаратную схему. Клиенты получают её вместе с состоянием игры; их локальные назначения кнопок сохраняются. В лобби роли подписаны по устройству и порту, включая два разъёма J-Cart. Для геймпадов источник — локальные назначения P1, для указательных устройств — первое подключённое устройство соответствующего типа. Несколько участников могут управлять одной ролью: кнопки объединяются, относительное движение мышей складывается с ограничением диапазона, для абсолютных координат применяется стабильный приоритет участника.

Относительное движение мыши расходуется только когда сетевой кадр принял ввод. Очередь движения ограничена, сброс фокуса отменяет накопленный ввод. На кадр не создаются дополнительные объекты или файловые записи.

Протокол сети — 5. Размер вклада участника остаётся 7 байт, канонический ввод кадра — 40 байт. Запись управления остаётся формата v2; старый v1 читается. Координаты существующего поля ввода используются по типу устройства: прицел, относительное движение мыши или абсолютное положение Paddle.

Нативное состояние ядра дополнено необязательным блоком протоколов устройств размером 128 байт внутри уже выделенного буфера: фазы геймпадов, адаптеров, мышей, Paddle и пистолетов. Размер нативного состояния не увеличен. Поля записаны явно, без указателей, padding и зависимости от Windows/Linux. Старые состояния без блока принимаются с прежним сбросом фаз. Версионный контракт ядра обновлён; несовпадение версии старой записи остаётся предупреждением и не блокирует воспроизведение.

## Обновление 0.19.1

Страница управления уплотнена; статические обучающие абзацы убраны. При стандартном окне 1100×720 внешняя прокрутка не нужна для проверенных геймпада с шестью кнопками, Mouse, Paddle, Menacer, Justifier и Light Phaser; таблица шестикнопочного геймпада также помещается целиком. На меньшем экране или при увеличенном системном шрифте прокрутка остаётся доступной. Ошибки применения выводятся у кнопок окна вне прокрутки; автоматически выбираются конфликтующие система, игрок и вкладка.

Захват на Windows/X11 использует Qt grab и возврат скрытого указателя в центр; на Wayland — стандартные relative-pointer и pointer-constraints с отдельным указателем. На Qt 6.4 соединение Wayland берётся через QPA, а доступная мышь определяется по возможностям устройств Wayland. Начиная с Qt 6.5 используются публичные интерфейсы Qt. После освобождения накопленное движение и нажатия сбрасываются. Отключённая галочка возвращает прежний свободный режим. При отсутствии поддержки захвата оконной системой выводится краткое сообщение. Для сборки Wayland backend нужны wayland-client, wayland-protocols и wayland-scanner; бинарный Linux-архив собран с ними.

Проверки 0.19.1: `osd_tests --pointer-only` — свободный/захваченный ввод Mouse, Paddle и пистолета, активационный клик, кнопки, Esc, потеря фокуса, выход указателя, крайние координаты; `debug_menu_tests ROOT --controls-layout` — настоящее окно настроек, отсутствие прокрутки и постоянно видимая ошибка применения с выбором конфликтующего порта. Обе проверки выполнены через Qt offscreen, без захвата Windows рабочего стола. Windows и Linux собраны; нативный захват на живом Wayland compositor отдельно не проверялся.


## Controls usability (0.20.2)

Settings present the system and adapter first, input capture/background preferences next,
then tabs for the available logical ports with Commands last. The commands page identifies
which port's physical-pad commands are being edited. The settings section and controls
profile/port/tab selection survive closing the dialog in memory only, and reset on app exit.
Draft binding changes still require OK; Cancel does not save mappings.

Double-clicking a diagram button or mapping row starts capture. Selection is red and the
visible footer shows capture feedback in green, errors in red. Reassignment replaces the
conflicting binding within the edited player and profile, including automatic pad mappings
and command bindings; other players can still intentionally share a keyboard/gamepad.

Capture arms each physical control independently. Inputs already held at entry are ignored
until released; a held or drifting axis no longer blocks a new button. A centered stick can
move directly from one extreme to its opposite between polls without losing that wizard
step. Axis state is sampled only by the existing capture polling and vectors are reused;
there are no new timers, file writes or allocations in normal gameplay.
