# Прямая сетевая игра (0.13.0)

В меню «Сетевая игра» выберите создание или подключение. Для создания достаточно
нажать «Создать»; пароль необязателен. Адрес для приглашения определяется в фоне:
сначала через UPnP у роутера (только чтение внешнего адреса), затем при необходимости
коротким HTTPS-запросом к ipify или icanhazip. Ключ приглашения, пароль, ROM и игровые
данные этим сервисам не отправляются. Запрос выполняется при создании сеанса или
явном повторе; постоянного опроса нет. Если автоопределение не удалось, можно повторить
его или задать адрес вручную в дополнительных параметрах создания.

Для проверки двух экземпляров на одном компьютере используйте «Копировать для этого
компьютера»: это приглашение с адресом `127.0.0.1`, также работающее при отсутствии
интернета. Оно предназначено только для того компьютера, где создано лобби.

Игровое соединение прямое: матчмейкинг, ретрансляторы и STUN не используются.
Порт по умолчанию — TCP 33445; его можно изменить в дополнительных параметрах.
Автоопределение адреса не открывает порты и не обходит CGNAT. Доступность порта
и настройки роутера остаются ответственностью игроков. Поддерживаются IPv4,
ручной IPv6 и имя узла; автоматический внешний адрес сейчас определяется для IPv4.

Приглашение содержит адрес, порт и случайный ключ этой сессии. Дополнительный пароль
можно сообщить отдельно или скопировать вместе с приглашением отдельной кнопкой.
Закрытие окна лобби скрывает его; выход из сессии выполняется отдельной командой.
Хост начинает игроком 1. Все новые подключения — зрители. Хост назначает роли
себе и другим; несколько участников могут занимать один игровой порт.
Каждый использует свои назначения первого локального контроллера. Кнопки одного
порта объединяются через OR, противоположные направления нейтрализуются. Уход
участника убирает только его вклад.

Хост открывает и меняет игру; проверка файлов выполняется отдельным рабочим потоком.
Другие участники открывают свою копию или явно нажимают загрузку, если хост разрешил
передачу. Совпадение проверяется полным SHA-256 канонического набора файлов.
Разные имена одинаковых ROM нормализуются; в CUE/M3U нормализуются имена треков.
Различия структуры CUE, включая комментарии, могут требовать скачивания копии хоста.
BIOS не передаются: каждый устанавливает соответствующие BIOS самостоятельно.

Передача читает блоки по 64 КиБ и сохраняет проверенные части для продолжения.
Из архива берётся выбранный ROM; для CD передаются только объявленные файлы игры.
Ссылки за пределы папки исходного образа и символьные ссылки запрещены.
Готовые загрузки лежат в `data/netplay/downloads/`; существующие пользовательские
файлы не заменяются. Передача сама по себе не означает согласие на запуск другого
невыбранного файла: запускается проверенный входной файл набора.

Пауза, сброс/питание, ускорение, перемотка, состояния и читы упорядочиваются хостом.
Хост может разрешить эти команды назначенным игрокам; зрители их не выполняют.
Сетевые быстрые сохранения и SRAM/RTC/BRAM изолированы в
`data/netplay/sessions/<идентификатор>/`. Запись состояния по сети ограничена одной
операцией в секунду. Обычные сохранения одиночной игры не перезаписываются.
Выход из сетевой сессии выгружает сетевую игру. Запись управления и учёт достижений
в этой версии во время сетевого сеанса отключены.

Потеря фокуса, меню и настройки не останавливают общую игру. При потере игрока
хост ждёт восстановления до 15 секунд, затем освобождает его вклад и переводит
в зрители. Клиент повторяет подключение с тем же локальным идентификатором.
Отключение зрителя не приостанавливает игру. Переноса хоста нет.

Идентификатор клиента — локальный ключ Ed25519 в `netplay-identity.key` рядом с
настройками; закрытый ключ не отправляется. Постоянные блокировки находятся в
`netplay-bans.json` рядом с ним и управляются в настройках. Удаление своего ключа
создаёт новую личность: это не система глобальных аккаунтов или неустранимых банов.
Сетевой канал использует TLS-PSK через OpenSSL; Windows-сборка содержит нужные DLL.

## Синхронизация и ресурсы

Ядро остаётся на единственном потоке эмуляции. Хост определяет фактический ввод
каждого кадра, клиенты выполняют те же кадры. Для единственного владельца порта
клиент может предсказывать до 6 кадров и исправлять их откатом; история отката
ограничена 64 МиБ. Зрители и участники совместно занятого порта ждут подтверждённый
ввод без локальных догадок. Это центральная авторитетная модель с клиентским
откатом, а не полноценный распределённый GGPO с откатом хоста.

Откат повторяет только ядро: звук, уведомления, записи на диск и достижения не
воспроизводятся повторно. Контрольный хеш памяти проверяется раз в 120 кадров;
расхождение вызывает получение полного состояния. Переходы времени используют
новую эпоху, чтобы старые кадры и подтверждения не смешивались с новой линией.
Состояние включает SRAM, RTC и CD BRAM, настройки, BIOS, устройства и читы.
Версия приложения и совместимость ядра должны совпадать.

Очередь worker→GUI ограничена 64 кадрами и одним исходящим снимком. Снимки и ROM
передаются с подтверждениями блоков, без накопления файла целиком в очереди сокета.
Распаковка состояния ограничена 128 МиБ; размеры превью проверяются до декодирования.
Вне сетевого сеанса сетевые таймеры и сокеты не работают.
