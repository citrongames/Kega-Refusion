Aq Renkan Awa / Ah Q Lianhuan Pao:

  MAME aqlian называет этот дамп unprotected и не задаёт специального slot.

  сохраняет последний байт cart.hw.regs[0]; чтение остаётся open bus.
  Банки ROM не переключаются. Это конкретный пробел модели серийного порта,
  не основание придумывать банкинг.
- Входы: 0x0FF322 init/write-enable, 0x0FF34A read(A0), 0x0FF362 write(A0).
  Их JSR-вызовы видны в игровом коде 0x028E0A/0x028E62/0x028EA0/0x028F0A/
  0x028F74/0x028F80. Это статические вызовы; достижение при вводе не измерялось.
- Порт байтовый 0x400001. CS=выход 2, CLK=выход 1, DI=выход 3, DO=вход 0.
  0x0FF422 поднимает CS, 0x0FF430 опускает CS; 0x0FF43E/0x0FF44C задают DI;
  0x0FF456 поднимает и опускает CLK.
- 0x0FF400 выдаёт START (DI=1), затем 8 бит команды/адреса MSB-first.
  0x0FF322 передаёт 0x30: EWEN (разрешить запись).
  0x0FF37A передаёт 0x80: READ с адреса 0, затем читает 64 последовательных
  слова по 16 бит MSB-first в (A0)+, после чего снимает CS.
  0x0FF3B0 для адресов 63..0 выдаёт 0x40|addr: WRITE, затем 16 бит слова
  из (A0,addr*2), снимает CS, снова поднимает CS и ждёт DO=1 в 0x0FF3EC.
- Save 0x028D3A читает 128 байт в 0xFF0C24, выбирает одну из четырёх 32 байтных
  записей, копирует игровую запись из 0xFF36BC, пересчитывает сумму и
  вызывает write в 0x028E62. Load 0x028E78 читает те же 128 байт, проверяет
  сумму записи и копирует 32 байта в 0xFF36BC. Диагностика 0x028F02 после
  записи сравнивает прочитанные 128 байт. Это сохранения данных, не только защита.
- START+8 бит, опкоды 01/10, EWEN=0x30, 6 бит адреса,16 бит слова и sequential
  read совпадают с existing eeprom_93c.c. Модель протокола подтверждена ROM
  и исходниками; чип/плата физического картриджа не изучены.
- Возможный адаптер: DI3->DI0 перед eeprom_93c_write; CS2/CLK1 совпадают,
  read возвращает DO0. Нельзя включать глобально: existing 93c используется
  SMS, MD его сейчас не инициализирует. Нужны точное распознавание Aq,
  MD-карта чтения/записи, начальные линии, power/reset без потери 128 батарейных
  байт и правильный порядок загрузки. Следует исключить ложную параллельную
  SRAM-карту для serial-device.
- Нужна сериализация T_EEPROM_93C: cs/clk/data/cycles/we/opcode/buffer/state
  (и enabled при использовании). md_cart_context_save/load сохраняет
  cart.hw.regs, но не транзакцию 93c. Добавление struct меняет native layout:
  нужны версия/длина и старые readers по контракту проекта. Проверять надо
  restore посреди команды, смену игры, power reset и батарейную перезагрузку.
  Здесь реализация и runtime-проверки не выполнялись.

Для независимой проверки использован исходный пользовательский ROM2C6CBD77,
без изменения ни одного его байта. В изолированном процессе заданы только
регистры 68000, стек и диагностические входные/выходные буферы рабочей RAM.
По одной инструкции исполнялись настоящие подпрограммы ROM с ограничением
100000 инструкций на вызов; после RTS выполнение останавливалось до исполнения
возвратного адреса. Нового кода в ROM/RAM не добавлялось.
- 0x0FF322 (EWEN) завершилась за 142 инструкции.
- 0x0FF362 записала все 64 слова за 22217 инструкций, выполнив 64 опроса готовности.
- 0x0FF34A прочитала 128 байт за 10058 инструкций/1024 читаемых бита.
- Полученные 128 байт в рабочей RAM и RETRO_MEMORY_SAVE_RAM побайтно совпали
  с диагностическим входом, включая порядок байтов/слов, без подгонки ответа.
- Сохранено состояние. Затем первые 128 байт батарейного буфера в изолированной
  памяти процесса затёрты диагностическим шаблоном; unserialize восстановил
  исходные 128 байт. Повторный вызов настоящей 0x0FF34A снова вернул точный вход.
  Это roundtrip памяти батареи и native state, не запись пользовательского
  файла сохранения на диск; файловый путь проверяет основной integration-test.

Тот же протокол и state-roundtrip прошли в четырёх конфигурациях:
- Обычный MD: active=1, размер состояния 1036288 байт.
- Принудительный CD: system_hw=0x84, features=1, размер 1036288 байт.
- Принудительный 32X: system_hw=0x80, features=7, размер 1572087 байт.
- CD+32X: system_hw=0x84, features=7, размер 1572087 байт.
Активность реальных дополнений проверена по значениям ядра, не только
по запрошенным опциям. Во всех режимах чтение/запись через порт 0x400001
сохранились после наложения карты и загрузки состояния. Все вызовы вернулись
штатно и все четыре изолированных процесса завершились exit0.

Независимый просмотр реализации подтвердил:
- Узкий detector исходного дампа; DI3 адаптируется к существующему DI0,
  CS2/CLK1 сохраняются. Остальные адреса страницы передаются прежней карте.
- Поддержка MD/Z80, повторное наложение после CD-карты; legacy-карты
  ошибочной параллельной SRAM ниже 0x400000 снимаются при восстановлении.
- Протокол и 128 байт входят в версионированный 160 байтный трейлер с CRC,
  проверяемый до сброса машины. Обычный native layout и публичный STATE_SIZE
  сохранены. Старый untagged state сбрасывает транзакцию, сохраняя battery.
- Идентификаторы recording/network для Aq изменены отдельно; другие ROM
  сохраняют прежние идентификаторы.
Не найдено дополнительного подтверждённого дефекта адаптера в этом просмотре.
Это проверка реальных ROM-подпрограмм и наложений, не полный игровой Save UI.

Артефакты: build/verification/pirate-groups-2-4/aq-real-rom-{md,cd,32x,both}.txt
и aq-rom-call.cpp. Временная копия ядра и ссылки на BIOS после проверки удалены;
исходные BIOS/ROM/сохранения пользователя не менялись.

Временные инструменты наблюдения, снимки и промежуточные JSON удалены после
переноса результатов в этот отчёт. Исходные ROM сохранены без изменений.
