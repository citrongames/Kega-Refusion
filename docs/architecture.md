# Architecture and current boundary

Kega Refusion 0.11.1 is a standalone C++17 / Qt6 Widgets application for Linux and Windows. It supports cartridge and Sega CD image loading and input recordings through a pinned Genesis Plus GX libretro core; it is not yet the complete feature list from info.txt.

## Ownership

`MainWindow` owns presentation and routes actions. `InputManager` owns SDL device discovery, per-system/per-player mappings and keyboard/pad state, including a transient movie hardware overlay that never replaces saved preferences. `GameView` paints copied RGB frames and upper-left OSD with the embedded Cyrillic-capable pixel font. `AudioOutput` owns Qt Multimedia output on the GUI thread. `EmulationSession` runs a dedicated emulation thread and owns `MovieSession`; `MovieTape` owns the bounded input timeline and file format. GUI actions enqueue commands; only the emulation thread calls `LibretroHost` and core functions. Input masks are atomic, latched once per frame. Core callback buffers are copied before returning.

`LibretroHost` dynamically resolves the libretro API; this keeps core-specific calls out of UI. 32X devices and SH2 execution are integrated into the existing GPX core, sharing its MD and Sega CD engines. A process-wide owner prevents concurrent instances of the non-reentrant core. This is an explicit current limitation, not a general-purpose multicore host.

## Timing and persistence

Frames use the core-reported rate and a steady clock. Fast-forward targets the selected 2x/3x/4x/6x/8x/12x/16x/32x rate, or runs uncapped (factor zero), and suppresses audio. While accelerated, it skips rewind capture and unseen video rendering through GET_AUDIO_VIDEO_ENABLE; presentation is limited to about 60Hz of wall time. The core continues advancing CPU and audio synthesis state, while the host omits PCM copies. Neither the hard audio-disable flag nor fast-savestate flag is used. Entering accelerated execution clears rewind history; normal execution starts a new continuous history after the gap. RGB565/RGB555 conversion uses Qt conversion routines. AudioOutput receives PCM through direct thread-safe calls, with a bounded software queue and coalesced GUI wake. A 30ms prefill precedes playback, requested sink buffer is40ms, target combined occupancy35ms. Partial writes are retained. Queue feedback gently adjusts the monotonic frame period within ±0.5%; missing/stale feedback falls back to nominal core timing. Device backend and hardware latency remain additional. FramePacer preserves absolute deadlines across short scheduler jitter and avoids long catch-up bursts after stalls. Slot queries do not reset the clock. Video delivery coalesces to the latest frame; OpenGL requests swap interval1 on native screens, with raster fallback.

Changed battery RAM is saved atomically after a settling interval, at most once per 30 seconds, and flushed on game switch or clean shutdown. Save filenames use the original ROM/member or current disc basename. Invalid existing battery saves are preserved, with writes disabled for that session. Quick states include a format marker, ROM hash, core-binary hash, payload hash and length. Incompatible/truncated/corrupt states are rejected before reaching the core. Slots are 0 through 9. QSaveFile avoids partially overwritten save files.

Genesis Plus GX declares platform-dependent serialization. The first state format deliberately requires the same core binary; Windows/Linux quick-state interchange and compatibility across core updates are not promised. Battery saves use raw core memory and are independent of quick-state envelopes.

## Deferred scope

Other specialized peripherals, netplay, video capture, Lua and debugging tools are not implemented. These will be added in testable steps. No promise of full ROM collection compatibility or all-platform movie determinism is made from generated-ROM checks.

Normal core file-state restoration resets sound resampler history, so immediate PCM bytes after loading a state are not guaranteed identical. The core fast-savestate flag keeps audio history only in global process memory and must not be enabled for file states or assumed to support a history of multiple snapshots. A dedicated full-audio serialization solution is needed before claiming audio-exact rollback.

Wider determinism claims still require longer runs and coverage across supported content and platforms; the first movie format does not establish cross-core or cross-platform compatibility. Shader rendering remains separate from original emulation output and timing.

## Input and controls (0.2)

SDL2 runs on the GUI thread and is polled every 8 ms. Known controllers use SDL logical controls; unknown joysticks expose raw buttons, axes and hats. Automatic defaults remain distinct from explicitly assigned raw controls. Stable device keys use GUID, serial where available, and a collision-free ordinal for identical devices. Two player masks are merged from keyboard and pad input and passed atomically to the emulation thread.

Gameplay input is disabled during modal dialogs, menus and loss of focus. Command edges rearm only after release, preventing a held reset/load/fast-forward control from firing again on refocus. Capture waits for neutral input, handles trigger rest positions and times out after ten seconds. Unplugging clears held state. Legacy keyboard settings migrate on first use.

ControlsDialog keeps local drafts per system and player; Save applies them and Cancel discards them. ControllerDiagram paints four system-specific diagrams and supports selecting a target by clicking it. Commands have a separate mapping tab. OSD contains only the latest action result/slot notice and active pause/fast-forward indicators, all in the upper-left corner. Resuming or returning to normal speed removes its indicator silently. General core/device/menu/FPS notifications do not enter OSD. Disabling OSD clears transient notices and suppresses all drawing; enabling restores current statuses only. Reset/save/load notices originate from successful core command completion, not from attempted requests. Fullscreen hides the menu; Esc toggles it without leaving fullscreen.

The chosen ImageGen KR icon is embedded both as a Qt resource and as the Windows executable icon. Source and generation prompt are retained in assets/ and docs/icon-design.md.

## Layout-independent keyboard input (0.2.1)

Keyboard defaults and stored mappings use Qt key identifiers for US physical key positions. Windows Set-1 native scan codes and Linux XKB keycodes normalize printable keys before gameplay or shortcut dispatch; release uses the same identity even after a layout switch. Older Cyrillic key identifiers migrate to their corresponding positions. Non-text/keypad identities remain Qt keys. Controls capture uses the same normalization and displays canonical key labels.

Digits 0–9 select state slots, including keypad digits with Num Lock enabled. They are reserved in the editor, mapping load/save and runtime input. Existing digit bindings cannot shadow slot selection. ShortcutOverride prevents Qt's logical shortcuts from competing with handled physical pause/mute/reset commands.

## Archives, rewind and pause reasons (0.3)

RomArchive lists and validates ZIP/7z entries, then returns the selected ROM bytes in memory. No member path is extracted. The GUI prompts only when multiple supported cartridges exist. LibretroHost exposes retro_game_info_ext during retro_load_game: Genesis Plus GX uses this interface to consume ROM bytes; the older retro_game_info.data alone is insufficient for this core. Archive member names determine the system profile and readable save basename. Packed and unpacked ROMs with the same filename therefore share states and SRAM. See docs/archive-support.md for dependency versions and resource bounds.

RewindBuffer records every second emulated frame during normal forward execution; fast-forward does not record history. It retains a current raw core+SRAM/RTC and RGB anchor plus a deque of reverse patches. Each patch stores skipped equal runs and the old changed bytes, then compresses that change stream. Dense changes and different sizes use a full compressed older block. State and pixels have independent patches, preserving exact matching cached images. Restoring applies the newest reverse patch, updates the anchor and removes that patch. Changes of image dimensions are supported. The byte limit accounts for retained QByteArray capacities of anchors and patches plus entry metadata; transient work and allocator overhead are additional. Cached video corresponds to that checkpoint, so stepping backward restores state and displays the matching image without simulating a new forward frame. Rewind mutes audio and clears queued samples at both boundaries. Normal resume regenerates audio; byte-identical PCM rollback is not claimed. Restoring an older point discards its future. The oldest retained point remains frozen while the rewind control stays held. Load/reset/new ROM/history-option changes clear history. History is capped at a configurable 16–1024 MiB (128 MiB default) plus temporary work buffers without a duration or checkpoint-count cap; available duration depends on retained data size. No periodic battery-file writes occur while rewinding.

Manual pause and background pause are independent. Returning focus clears only background pause; manual pause is retained. A rewind request can inspect older frames during manual pause, but background pause blocks rewind. R is reserved for rewind and is normalized by physical key position. The command is appended to the gamepad command IDs to preserve saved bindings.

The slot OSD follows FCEUX's filled-versus-empty ten-cell concept at the user's preferred upper-left location. The selected slot is outlined and labelled occupied/empty. The worker queries file presence on selection and refreshes the occupancy mask after successful saves. Occupied means a slot file exists, not that its contents have passed load validation. Slots disappear after two seconds and obey the global OSD switch. No save manager or permanent status panel is added.

## Regions, resets and image filters (0.4)

Core option overrides are reapplied when GPX registers its option table. GET_VARIABLE_UPDATE reports changes; GET_SYSTEM_AV_INFO/SET_SYSTEM_AV_INFO keep fps/sample rate current. Region selection uses native core options auto/ntsc-j/ntsc-u/pal. Blargg options also use the native core implementation. Changes are applied on the next forward core frame (after resuming if paused); rewind history and queued audio are reset around the transition so timings and images do not mix.

Soft reset calls retro_reset, which GPX maps to gen_reset(0), retaining volatile RAM. Hard reset flushes writable battery memory, unloads/reloads the retained ROM bytes through game_info_ext, restores SRAM/RTC and reestablishes controllers/AV information. No archive rescan or member selection is required. Rejected existing save files remain protected. Both reset paths clear rewind/audio; manual pause remains independent.

Filtered frames carry validated native-width/native-height metadata independently of the expanded Blargg RGB buffer. GPX MD and SMS NTSC output geometry is inverted using the core base viewport and supported crop sizes; Game Gear and interlaced heights are retained. Square-pixel aspect and integer scaling use native geometry on both raster and GPU paths. Rewind preserves this metadata with each frame.

GameView preserves the raw emulation image for history and delegates native presentation to a child OpenGL widget. ShaderPipeline implements serial GLSL multipass presets, parameters and per-pass scaling/filtering. The built-in Dither blending preset uses an original Kega Refusion GLSL shader under the project's GPL-3.0-or-later terms. Its single source-resolution pass reconstructs local color coverage in shaded ramps from sparse dots, alternating lines and checker patterns. Confirmed high-contrast patterns use stricter extent checks. The blend strength is adjustable. OSD is painted after video filtering. Unsupported Slang/Cg and unsupported preset features are rejected. Context/shader failures leave raster video available. Saved selections of the retired built-in GDAPT resource migrate to Dither blending without copying GDAPT parameters; external presets keep their paths and settings. Blargg modes and GLSL presets remain mutually exclusive.

Checksum autofix is optional, default off. Original content and its SHA-256 remain unchanged; a separate implicitly shared coreContent copy receives the two-byte MD header patch before load/hard reset. Canonical SEGA headers, GPX-recognized swapped headers and SMD layouts are detected; ambiguous non-MD data is untouched. Sum calculation uses normalized big-endian words after0x200, then maps0x18e/0x18f back to the original layout. Toggling only changes the next-load policy; the current session is untouched until a subsequent load or explicit hard reset. A self-checking original68000 fixture verifies boot rejection/acceptance, original file preservation and unchanged save identity for raw/SMD/swapped/archived content.

On Windows, FrameWaiter uses a high-resolution waitable timer rather than generic Sleep-granularity waits. Older Windows fallback requests1ms timer resolution for the worker's lifetime and restores it on exit. There is no busy-spin loop. Linux uses an absolute monotonic sleep.


## Sega CD (0.5)

DiscMedia validates CUE references, ISO headers, CHD signatures and up to four M3U members before disturbing the current game. Only small headers and file metadata are read at this stage; full disc/track hashing is not performed. ISO CUE sidecars are resolved explicitly. The host expands M3U itself, avoiding the pinned core's naïve relative-path parser. Real full_path/dir/name/ext and null data are supplied through GET_GAME_INFO_EXT. Paths exceeding the core's 255-byte UTF-8 image buffer are rejected.

SegaCdBios recognizes user-provided 128 KiB images by observed fingerprints or strict header/checksum checks, imports missing regional slots with QSaveFile, and never overwrites existing BIOS files. Host preflights the detected/forced region; CHD region is decoded by the core. At least one BIOS is required for CHD auto mode and a load failure reports all regional BIOS statuses.

The legacy disk interface is copied at registration and retained as a capability even after the core unregisters it for a cartridge (it re-registers only at init). Every use is gated on loaded CD content. Mount operations eject, select/replace, then close. Failed mounts attempt to remount the previous image and restore its volatile state. Commands run only on the emulation thread; queued discStateChanged updates drive UI. Automatic in-game tray changes are also observed. Disc operations clear rewind/audio; checksum autofix applies only to cartridges.

CD quick-state identity includes the original disc basename, region override and installed BIOS fingerprints. The same disc must be mounted before restoring state because the core serializes CD positions but not its TOC/path. Each disc has separate slots. Hard reset retains the current image and rebuilds the disc list. The battery-only core extension retains the pinned core's prior state identity; old quick states remain compatible.

CD BRAM initialization and formatting remain owned by Genesis Plus GX. Standard RETRO_MEMORY_SAVE_RAM and core serialization do not expose/include internal CD BRAM or backup-cart RAM. The small optional extension exposes validated const memory views and existing regional/cart paths; host management disables the core's direct unload writer. The host persists existing .brm formats through BatterySave, without inventing .srm files. Ordinary CD video/CPU/drive rewind is supported within a mounted image, but game-written BRAM is not undone by ordinary rewind/state load. Movie snapshots explicitly include CD BRAM alongside native state; the normal state boundary remains unchanged.


MP3 CD audio uses a VFS v3 adapter and unmodified, pinned minimp3 (`ea99364f61c14656440e8d77e9c233ccf3124633`, CC0). A small in-memory CUE rewrites MP3 track names to virtual WAV aliases; the original data track is a read-only file alias. Neither converted audio nor ISO copies are written to disk. The core receives a 44-byte RIFF header followed by on-demand 44.1 kHz stereo signed-16 PCM. Each open MP3 stream retains minimp3's 128 KiB compressed input buffer, an 8 KiB output block, codec state and its compressed-frame seek index. MP3 frame/index scanning establishes length; no full PCM buffer is built. Header probes/seek-to-end are cheap cursor operations; decoder seeks occur only when audio bytes are actually read. Odd-byte reads and repeated random seeks are supported. Source MP3 is limited to 256 MiB and 100 decoded minutes; non-CD sample rates/channels are rejected instead of silently resampled.

The VFS passes native files, BIOS and BRAM reads through QFile, including nontruncating UPDATE_EXISTING writes. Virtual paths are read-only; handles own their backing state after registry changes. Registrations are rebuilt from at most four active discs, so disc swaps do not accumulate aliases indefinitely. Initial CD mount does not reopen the same disc through disk callbacks, avoiding repeated audio indexing. Disc opening and selection check source metadata without rehashing audio tracks. A small PCM-byte counter supports diagnosing whether CD music is actually being decoded during performance measurements.


## Persistence and resource discipline (0.6)

BatterySave caches the last persisted and observed bytes, so an unchanged-memory check does no disk I/O. The emulation thread polls once per real-time second (including pause, excluding rewind), waits two seconds of stability and spaces automatic writes at least 30 seconds apart per file. Continuously changing memory reaches a 30-second dirty deadline. Explicit unload/game change/hard reset flushes pending changes immediately. Failed periodic writes are throttled too. QSaveFile atomically replaces one previous-version .bak before atomically committing the main file; a failed backup prevents replacement. The first save seeds .bak with that version. Empty unused cartridge SRAM creates no files; malformed existing saves are not overwritten. The existing cartridge SRAM rewind envelope is preserved; CD BRAM still lies outside core state/rewind.

The committed core patch exports only optional BRAM management/accessors and a state-ABI identifier. The ABI explicitly retains the previous Windows/Linux core state hashes. Compatibility checks load a quick state written by the previous binary and compare 60 subsequent video/audio frames. Raw serialized YM2612 structures contain rebuilt native pointers, so their literal addresses are not a cross-library equality criterion.

Audio selection stores a stable device ID, with empty ID meaning current system default. Hotplug refreshes the effective device, reopens only if its ID changes, and retains a missing explicit preference while temporarily using the default. The audio queue reuses its bounded byte buffer instead of building a new retained-queue copy on every append.

A screenshot temporarily suppresses OSD rendering during framebuffer capture, crops the game rectangle and restores presentation without changing OSD settings. PNG is the default; JPEG uses quality 95. New-only file creation and a collision suffix prevent overwrites. F12 is reserved from gameplay mapping; images go to data/screenshots. The Windows package includes the JPEG image plugin.

The UI forwards its validated archive member index/name/size to the worker; extraction still checks the member metadata and decoder limits, avoiding the former redundant full listing/decompression pass. MP3 remains streamed with bounded decode buffers and no temporary WAV files. Shader source and intermediate targets share a 128 MiB allocation budget. These limits describe owned payloads/allocations; driver and allocator bookkeeping is additional.

## Integrated 32X timing and video

The bounded scheduler must finish both CD CPUs at each shared frontier. A SUB-CPU communication-register write may wake an idle MAIN-CPU at an earlier timestamp. The scheduler retries that slice before committing its frontier; otherwise the final scanline can leave MAIN behind the frame subtraction and stall the next frame. Already executed SH2 time is monotonic and is not replayed during catch-up. Sega CD GFX stores a signed frame-relative clock in a wrapping uint32 field. Deadline selection and dispatch must sign-extend it through int32 before widening; zero-extension can postpone an active operation by a full 32-bit clock wrap.

Video uses three fixed tagged scanline records, covering GPX remaps of the previous/current/next line. Mode, priority, shift and display bank are latched before active display; decoded 32X colors are reused if the MD layer is remapped later. A transient watched-bank mask synchronizes framebuffer writes before mutation only when they can affect a pending row. Skipped frames retain event timing but omit pixel work. H32 maps MD and 32X samples on a shared phase grid without a supersampled frame buffer. Timing provenance and remaining approximations are recorded in `src/core32x/video/PROVENANCE.md`.

Virtual controller-port connection is independent of physical keyboard/gamepad selection. Defaults connect player one and leave player two empty. Per-system settings are queued on the emulation thread before loading content; live connection changes clear rewind history. Unchanged port settings never reset the core input protocol during state restoration.

Game loading has a separate on-demand overlay, independent of gameplay OSD. It is presented once before any synchronous archive scan, remains visible while the emulation thread opens content, and clears on success/error/cancellation. It uses no animation timer and blocks duplicate open/drop requests while pending.

Save filenames use the original ROM/member or current disc basename. Cartridge data already loaded in memory retains its checksum for state validation and legacy hashed-name fallback; new writes use readable names. CD opening validates file metadata and a short boot header without hashing full tracks. Its state identity uses the selected name, BIOS and region. The path-derived digest in DiscMedia is only a private in-memory MP3 alias namespace.


## Controller artwork and rewind controls (0.7.4)

MD controller type is stored per profile/player and queued to the worker. GPX receives actual MDPAD_3B / MDPAD_6B device subtypes; Mode/X/Y/Z are masked in 3-button mode without deleting saved bindings. Type changes clear rewind/audio, and unchanged settings preserve core input protocol state. Other systems retain their native two-button devices. Master System Pause remains libretro START (the console NMI), separate from emulator pause.

Controller PNGs are embedded Qt resources, decoded only when their selected resource changes. Only the selected pixmap is retained. Hit paths and translucent pressed/selection overlays preserve interactive mapping without editing the artwork per frame.

Rewind memory changes clear history on the worker. Limits count retained QByteArray capacities and live entry metadata; transient encode/decode/image buffers, Qt control blocks and allocator/deque bookkeeping are additional. No memory is preallocated to the selected ceiling. Rewind progress uses checkpoint cadence (two emulated frames per snapshot), freezes the starting available duration, and emits remaining milliseconds at most 10 times per second while held. Zero stays visible at the oldest checkpoint until release. The OSD toggle affects display only.

In 0.7.5 the buffer has only an enabled flag and a byte ceiling; it has no time/count limit. The session still captures every two frames and derives the OSD countdown from actual retained snapshots. `emulation/rewindEnabled` replaces the old duration setting: legacy zero migrates to disabled, nonzero to enabled, and the old key is removed once. The old seconds submenu is replaced by a recording toggle; the memory ceiling remains in emulator settings.


## Light guns, cheats and frame advance (0.8.0)

Controller kind and aim source are stored per system/player, independently of physical device selection and the retained pad bindings. MD guns attach to hardware port B: one Menacer, or a Justifier pair; an optional ordinary pad occupies port A. Host callback-to-player mapping accounts for GPX compact device numbering and the third callback slot for pad plus two Justifiers. SMS Light Phaser uses its native port. Port changes run on the worker and clear history/audio; unchanged topology does not reset protocols during state restoration. With only port B's pad present, the compact GPX pad subtype is seeded before restoring empty port A.

GameView normalizes mouse positions against the actual game rectangle, including scaling and black bars. One logical gun can use the ordinary OS mouse; the other uses its assigned gamepad's left stick, or both use sticks. Stick integration uses elapsed poll time with a 32 ms cap and radial deadzone. The worker reads packed atomic coordinates and merges button masks without event-thread core calls. Reload is a virtual offscreen trigger action, avoiding dependence on available desktop space in fullscreen. Losing focus/loading clears held mouse buttons. There is no pointer capture/warp or global input hook. Two numbered colored reticles are drawn after raster/shader video and excluded from captures; OSD visibility does not affect aiming.

Cheats::Store validates bounded lists (4096 entries, 2 MiB file cap, at most 100 enabled native code components), normalizes native core formats and persists named per-game JSON atomically on changed lists only. No frame performs cheat file I/O. The host retains the active code sequence; description-only edits do not reapply patches or clear history. Core changes run between frames and clear rewind/audio. Soft/hard reset reapplies the retained list. Disc changes load that disc's list. The optional retro_kegarefusion_invalidate_code extension refreshes the 32X boot-page ROM shadow and invalidates SH2 translations only after patch changes, not per frame. No new SH2 RAM cheat format is advertised.

Frame advance is a queued worker command accepted only for a loaded, manually paused, non-background, non-rewinding session. It executes one frame with video enabled and audio output suppressed, publishes the image and preserves manual pause. Rewind capture keeps its ordinary two-frame cadence. The menu action advances once. A physical period key or mapped gamepad command advances once on the combined rising edge, then worker-owned hold timing starts after 350 ms at 30 frames/s. OS key repeat is ignored; release, focus loss and modal blocking clear the hold.


## Dialog pause and controller usability (0.8.1)

Modal presence is part of the existing background-pause condition, independent of the optional application-focus policy; WindowBlocked applies it immediately. Manual pause remains a separate worker state. Mouse events carry raw Qt button bits to the InputManager's per-kind/player binding lookup, then combine with keyboard/gamepad masks. There are no extra timers or per-frame settings reads. Explicit and automatic physical device assignment can share one device. The virtual controller selector uses None instead of a separate connection checkbox, retaining bindings while disconnected.

The close-game worker command flushes changed battery data before unloading and aborts on failure. Success clears pending video, input, audio and rewind state and notifies the UI to restore the empty view. It does not clear controller preferences or recent files.

A focused original 68000 handshake fixture checks Menacer/Justifier identification on port B, rejection on port A, button routing with or without a port A pad, and independent chained Justifier input. Actual T2 and Lethal Enforcers menu probes established that a lone gun leaves Start/menu input unavailable: explicitly connecting a pad on hardware port A and the gun on B allows their menus/game to advance. The host retains explicit device topology; it does not synthesize a hidden companion pad or mirror gun input into a pad.


The controller UI now follows physical MD ports: slot 0 is port A (pad/none); slot 1 is port B (pad/none/Menacer/Justifier). The optional second Justifier is slot 2 chained to slot 1, with its own bindings and aim source. It is exposed by a checkbox for port B Justifier, not by replacing port A. Three fixed input/aim slots pass through the UI, worker and host; queued port IDs use two bits. Callback mapping still accounts for GPX compact numbering and always-unrolled Justifier pair; an unconnected second gun returns neutral/offscreen input. Displayed crosshair numbers are independent of input slot indices, so the first gun remains cyan 1 and the second orange 2. The existing Light Phaser port arrangement for Master System is retained.


In 0.8.2 crosshairs use color without numeric labels. A per-system/input-slot showCrosshair preference defaults to true and is stored only when hidden. GameView gates only overlay painting, independently of gun connection, aim/button input, and OSD visibility. The control dialog edits this preference through its existing apply/cancel workflow.

## Input movies (0.10.0)

The File → «Запись» submenu starts recording only with a loaded game, from a power reset and normalized initial snapshot. `MovieTape` writes version 2 metadata, an initial full recording state (`KRMOV002`), run-length encoded input sampled once before each emulated frame, and a full end/resume state plus its frame cursor in the same `.krm`; version 1 recordings remain readable. The full movie state combines native core serialization with cartridge SRAM/RTC and Sega CD internal/cart BRAM. Playback is read-only and never edits the source. The recorded end state resumes recording in the same `.krm` in a later session without replaying the earlier input. A branch from playback or its finished pause creates a new `.krm` and identity while preserving the source. At the final playback frame the worker pauses with the game loaded; explicit takeover, or normal unpause after the end, returns to live control. Stopping recording saves and keeps the game open. Closing the window during recording queues game close, which saves and unloads under the movie battery-write guard before the window exits; on failure the window stays open and reports the error.

Each active movie has its own 0–9 slots under `data/states/movies/<name>_<movie-id>/`. A slot includes a full state, movie identity and its input prefix/cursor; integrity and prefix checks reject another movie or incompatible playback branch. Ordinary quick states are neither read nor written while a movie is active. Movie save/load/rewind remain available, subject to the user's rewind-history setting. An internal rewind checkpoint carries the trusted full movie state and frame cursor without a per-checkpoint digest; external `.krm` and slot files have full integrity checks. Recording after loading or rewinding to an earlier point truncates the abandoned future input. OSD shows recording/playback and a counter only while active and obeys the global OSD toggle. The unified Settings → «Запись» page stores a time (default, `hh:mm:ss`) or frame-count preference; time is derived from the frame rate stored in the recording metadata, including the game's region-specific rate.

All active movie modes, including the finished pause, guard normal battery files from writes. Movie configuration fixes core options, cheats, controller topology and the selected CD image; reset, region, cheats, Blargg core filter and active disc changes are blocked. Button bindings can change through a transient `InputManager` hardware overlay without persisting recorded port hardware. On explicit stop/takeover, normal user configuration is restored. Cartridge ROM content and required BIOS fingerprints must match; CD identity checks each source file's size plus its first/last 64 KiB rather than hashing the full image. CD image changes are blocked during an active recording. A stable exported playback contract is scoped to platform and architecture, allowing compatible core rebuilds without a warning; shipped 0.10.0 Windows/Linux recordings are recognized on their respective platforms. An unknown or changed contract displays a nonmodal OSD warning with recorded/current app versions and core builds but does not prohibit playback or resumption. Corrupt files, different games and native states that the current core cannot load still fail. Cross-platform native-state compatibility is not promised, and these checks do not prove deterministic behavior for every CD, 32X or other game.

The timeline is run-length encoded with a 64 MiB budget for input runs (1,048,576 distinct-frame runs, about 4 h 51 min at 60 frames/s in the changing-every-frame case); repeated input extends the duration. Reaching the run limit pauses and saves the accumulated recording. There is no per-frame disk I/O: the movie is written at creation and stop/close, and an explicit slot action writes its own state. Atomic movie replacement validates the previous file and keeps one `.bak` prior version. Full file checksums protect `.krm` and external slots; loading validates sizes and identities before restoring the core.

Plugin discovery occurs before `QApplication` loads its platform plugin. The executable directory is resolved from the native module path (`GetModuleFileNameW` on Windows, `/proc/self/exe` on Linux); a packaged `plugins/` directory takes priority while installed Qt paths remain available. Packaging no longer creates `qt.conf` and removes only the previously generated file with its exact known contents; custom files are preserved.


## RetroAchievements (0.11.0)

`AchievementsClient` owns the pinned rcheevos `rc_client` on the emulation worker. `AchievementNetwork` owns GUI-thread Qt Network requests and a persistent image-only disk cache. Requests/responses cross queued signals; neither HTTP nor image decoding runs inside a core frame. The constructor does not emit requests before the GUI connects its handlers. Anonymous/disabled operation makes no service requests. Every emulated forward frame, including skipped presentation frames at fast-forward, evaluates the achievement runtime. While paused/loading it idles at 100 ms intervals. Loading has a 15-second watchdog. Tables are rebuilt on relevant state changes or explicit requests, not every frame.

Host memory descriptors are copied when registered by libretro (the native core may use stack-local descriptor arrays), then mapped through `rc_libretro`. The raw byte order follows the official libretro mapping. Cartridge identification uses the SDK hash over original content, without checksum autofix; CD identification uses the first 512 decoded bytes exposed by the native core, avoiding full-image hashing and drive-position changes. IDs and hashes are cached outside the per-frame memory-read path.

Ordinary quick-state payloads optionally wrap native state and achievement progress in `KRHOST01` under the existing file digest. Existing raw payloads still load. In-memory rewind uses `KRACHRW1`, with its byte cost included in the existing memory budget. The achievement envelope `KRACT001` associates runtime progress with the game and signed-in account; file progress carries a digest, while trusted in-memory rewind avoids a redundant full-envelope digest. Progress is bounded at 2 MiB. Movie snapshots keep their original format; recorded-input playback/resume/fork suppresses evaluation, and movie slot loads reset condition counters.

All public Hardcore entry points are gated by `AchievementsHardcoreApproved=false` until RA approves this client's unique User-Agent. Worker restrictions are authoritative: UI actions alone cannot bypass them. Entering Hardcore requires a power reset and disallows native state loads, rewind, frame advance, cheats and recorded-input replay. Fast-forward and saving a state are allowed. Core cheat/region/timing options are checked against the SDK and local extensions; repeated pause attempts demote the session to Softcore. Server award responses do not independently confirm the Hardcore flag, so local mode must not be presented as proof of server approval.

Account persistence is separate from settings: username and reusable API token in `retroachievements-account.ini`, atomically replaced, no password or response logging. API responses are not disk-cached. Badge transfers have bounded bodies, image dimensions, concurrency and queues. Only official HTTPS API/badge endpoints are accepted; redirects are not followed. Qt's Windows Schannel TLS plugin is deployed with Qt Network.

Achievement enablement and notification enablement are independent. OSD only receives game-ready, unlocked, and Hardcore-completion messages; global OSD disable suppresses them as well. There is no anonymous offline achievement-definition engine in this version.


### Achievement presentation (0.11.1)

Achievement rows are emitted in stable ID order, independent of SDK lock-state buckets. `AchievementsDialog` uses a proxy with explicit numeric/localized sorting and dynamic re-sorting disabled: unlock/status updates change data on the existing row. Same-game updates do not reset the model, selection or scroll. Visible icon requests map proxy rows to the source, coalesce per event-loop iteration, and share the existing bounded image/network caches.

`GameView` keeps at most eight achievement popups, each visible for 4000 ms. Cards are rendered into a cached device-pixel-ratio-aware pixmap only at display, badge arrival or resize, then composited over the video. Expiry removes the card and schedules an update; it performs no core reset, network or file operation. Hiding notifications/global OSD and closing/loading games clears the queue. Late image arrivals do not restart the timer. Cards use one of six saved screen anchors (top/bottom × left/center/right), default top-left, and are composited last above action OSD without shifting its layout. Clean screenshots still omit overlays.

A 250 ms original two-note sound is precomputed once (24 KiB PCM). It mixes into existing frontend stereo PCM only while an audio sink is active and ordinary gameplay audio is running. It does not allocate a separate device, reopen a sink, read sound files or change sample counts/pacing. Inactive playback follows the original queue path; active mixing copies only a bounded chunk and saturates Int16 samples. Mute, clear and device changes cancel the tone. Sound has an independent saved preference, subordinate to notification/global OSD enablement.

Presentation behavior was compared with upstream RetroArch's `gfx/widgets/gfx_widget_achievement_popup.c` (4000 ms, queue of eight) and `cheevos/cheevos.c` (badge, unlock heading/rarity, title/points and optional sound). No RetroArch source or sound asset was copied.


On game recognition, MainWindow schedules both unlocked and locked badge variants for the complete set once. Background prefetch is limited to two concurrent downloads; visible/popup requests have priority. Valid images are stored atomically under `data/achievements/badges`, keyed by URL digest, without automatic deletion as explicitly requested. Decoded memory cache remains bounded at 16 MiB. A private lazy worker pool (one thread, five-second idle expiry) performs file stat/read/decode/atomic writes; at most two total badge IO/network jobs are active. Background cache hits only inspect bounded file metadata, while displayed images are decoded and validated on the worker. The GUI only schedules work and receives ready images. No progress/unlock event restarts the full prefetch; game change replaces the remaining background list.


### Interface and hardware options (0.12.0)

`Localization` loads bounded JSON catalogs once before the emulation thread starts. External Russian/English catalogs are shared by Windows/Linux; a compiled English catalog is the final fallback if external files are missing. Optional `data/languages` catalogs override bundled files. Strings are looked up in immutable maps without file access; language changes require restart. Persistent keys, command identifiers, paths, controller scan-code mappings and serialized formats remain untranslated. `languages/README.md` documents third-party translations.

FPS diagnostics are independent from action OSD and disabled by default. The worker counts completed native frames in one-second steady-clock windows and reports native-rate speed percentage. A diagnostic flag set only by emulated MD/SMS/GG controller-register reads is cleared at the start of `retro_run`; frontend libretro input polling never sets it. Game FPS is `native PAL/NTSC rate * framesWithInputReads / completedFrames`: an explicitly normalized estimate, not a universal logic/render rate or measured input latency. No frame copies, hashes, emulated RAM scans or disk access are used. Pause, rewind and timeline discontinuities invalidate samples. Achievement popups still composite last, over these counters.

Expansion preferences are pending host settings. They become actual core options only at load/power cycle. CD uses native Mode 1; 32X adds a boot-time `auto/connected` core option without replacing the core or cartridge mapper. BIOS checks precede destructive reload where possible. CD-forced load fails on missing selected-region BIOS instead of silently falling back. Ordinary cartridges retain Mega Drive achievement identity even with devices attached. Cartridge CD quick-state identity is distinct from plain MD and from MD+32X; recording configuration carries native options and fingerprints the firmware required by the recorded topology. Old recordings without the new 32X option retain automatic attachment.

Menu pause shares the worker's automatic pause input but not its manual pause state. A top-level menu-open latch bridges transitions between adjacent menus/submenus. Modal and popup visibility suppress gameplay input independently from focus-loss pause preferences. Background gamepad input is separately gated, never enables keyboard/mouse or emulator hotkeys, and releases latched buttons when disabled.

Achievement image-cache clearing cancels queued/background work and invalidates stale callbacks with a cache generation. The single IO worker drains preceding writes before deleting only owned URL-hash `.img` files; new requests wait until completion. Credentials, progress and unrelated files are untouched. The GUI never waits synchronously for cache deletion.

Core patches form an ordered receipt-managed stack. Updating an earlier layer unwinds known later layers and restores them with the new revision; conflicting edits are retained and reported. Unchanged receipts do not rewrite sources or rebuild objects.

## BIOS filenames and explicit save files (0.20.1)

BIOS roles are resolved from content in the portable `data/bios` directory. A valid canonical filename wins; otherwise valid candidates are selected in filename order, independent of extension. Invalid canonical files cannot hide a valid renamed image. Recognition retains at most 256 metadata records per BIOS family and no BIOS payloads; it runs only for explicit validation/loading. Core VFS aliases expose the expected role names without renaming or duplicating user files. The 32X loader uses the same VFS as Sega CD. Recording metadata keeps canonical role keys and fingerprints actual selected content, so a rename does not change identity.

The Emulation menu also saves to and loads from a chosen `.krs` file. The dialog suggests the game name and remembers the last directory. Normal saves reuse `KRSTATE1`; active recordings reuse their provenance-aware `KRMSLOT1` envelope and prefix checks. Missing files remain nonmodal notices. Explicit path operations are local worker commands and are host-only during netplay; successful host loading triggers the existing shared snapshot synchronization. Hardcore still blocks loading. No new automatic writes or background scanning are introduced.


## Native video recording (0.21.0)

`EmulationSession` owns `VideoRecorder`, a bounded single-producer/encoder-worker queue. Live capture is submitted once per forward frame, including fast-forward/step audio; GGPO rollback replays never enter this queue. Movie export uses the existing exclusive core and `MovieSession` read-only playback, bypasses device/wall-clock pacing and background pauses, and allows cancellation between frames. Input/configuration commands cannot change that pass. Achievements and battery writes retain the existing movie-playback guards. File/codec work runs on the encoder thread; normal emulation without capture never enters its mutex.

An optional core ABI enables an allocated raw scanline surface only during recording and exposes its borrowed pixels. MD/SMS/GG raster mapping occurs before NTSC/LCD and cursor overlays, while the 32X bridge copies the combined MD/32X native row before filtering. `LibretroHost::recordingFrame()` owns a copy, selecting the presented Link Cable side. Disable/deinit frees the surface. This is presentation-only and does not change state or recording compatibility IDs.

FFmpeg PNG RGB24 + AAC256 are muxed to fragmented MOV through Unicode-safe QFile AVIO, in one-second / 4MiB fragments. `skip_trailer` avoids retaining the complete fragment index. The video track clock is 60000 ticks/second; absolute frame timestamps are rescaled from exact core FPS to avoid long-term drift. Audio uses the original sample clock with encoder priming metadata. Resolution/rate changes open numbered parts without scaling, at most256 parts per recording. Queues are limited to8 frames of at most1M pixels plus bounded PCM; encoding retains no complete recording. NewOnly prevents replacing existing files.

Authoritative nonempty controller snapshots update UI input mappings without echoing configuration commands back to the session. Clearing the override still reapplies the local profile. This prevents the spurious protected-recording OSD at start without removing protection against actual incompatible user changes.


## Release packaging

Both platform build scripts select CMake Release. Packaging strips non-runtime symbol/debug sections from staged copies of the application, cores and runtime libraries; development originals remain intact. PE files carrying Authenticode signatures are preserved unchanged. Neither the core implementations nor the dependency/plugin set is reduced. Link Cable's second module remains a separate physical file for loader isolation.


### Live audio latency profiles

The frontend owns three local profiles; they do not change core sample rate, emulated hardware, recording/state compatibility, or peers' audio. Timing tuples (microseconds: combined queue target / prefill / software queue cap / requested device buffer and write high-water mark): Low 20000/15000/40000/20000, Normal 35000/30000/60000/40000, Stable 70000/60000/120000/80000. Normal exactly preserves the previous constants and is the fallback for invalid preferences. These values are buffering policy, not a promise of measured hardware latency.

`audio/latencyProfile` stores Normal=0, Low=1, Stable=2. Settings applies changes immediately, like master volume. Under the existing PCM mutex a change clears old/partial PCM, cancels a chime, invalidates clock feedback with the new target and queues a coalesced pump. The GUI thread resets/reopens only QAudioSink on the next PCM; paused/no-game switching leaves no sink running. Sample-rate/device changes retain the profile; repeated identical selections do nothing. Actual device buffer occupancy still comes from Qt rather than the requested size. No additional periodic work or per-frame allocations are introduced.
